01

认识 LCD1602

LCD1602 是单片机入门最常见的字符型液晶：能显示 2 行、每行 16 个字符。它内部集成了一块 HD44780 兼容的控制芯片，芯片里自带 ASCII 字模库，所以只要把字符的 ASCII 码写进它的显示缓冲区，字符就会出现在屏幕上。

三个核心概念

字符型：每个显示位置固定放一个字符（5×7 点阵），不能逐点控制，因此不能直接显示图片。

控制器 HD44780：它替你完成"把 ASCII 码变成点阵"的工作，单片机只需要给它发指令和数据。

自带字模（CGROM）：ASCII 的 0x20~0x7F 已固化在芯片里，写 0x41 就显示 A，写 0x30 就显示 0。

易错点CGROM 里没有中文字模——LCD1602 无法直接显示中文。要显示自定义图形，只能用 CGRAM 的 8 个自定义字符位（详见第 03 节）。

主要技术参数

参数数值
显示容量16 × 2 字符
芯片工作电压4.5 ~ 5.5 V
模块最佳工作电压5.0 V
工作电流2.0 mA（5.0 V 时）
字符尺寸2.95 × 4.35 mm（宽×高）
接口8 位并行（或 4 位），本教程用 8 位

02

引脚定义与接线

模块一共 16 个引脚。真正需要单片机控制的是 RS、R/W、E 和 8 根数据线；VSS/VDD 供电，VL 调对比度，BLA/BLK 给背光供电。

16 脚功能速查

脚符号功能
1VSS电源地（GND）
2VDD电源正极 +5V
3VL液晶对比度调节，接 10K 电位器
4RS数据/命令选择：0 指令，1 数据
5R/W读/写选择：0 写，1 读
6E使能信号：下降沿锁存数据
7~14D0~D78 位并行数据总线
15BLA背光正极
16BLK背光负极
只用写、不读，R/W 保持 0 即可本项目驱动没有用忙检测（用延时代替），每次写操作都把 R/W 置 0；也可以把 R/W 引脚直接接地，进一步省掉一根 I/O。

89C52 接线（本项目的接法）

LCD1602接法89C52
RS（4）→P2.6
R/W（5）→P2.5（本驱动置 0）
E（6）→P2.7
D0~D7（7~14）→P0.0~P0.7
VSS/BLK（1/16）→GND
VDD（2）→+5V

P0 口是开漏输出，做数据口时通常需要外接 10K 上拉电阻到 +5V。

03

显示原理：DDRAM 地址映射

HD44780 内部有 80 字节的显示数据 RAM（DDRAM）。每写一个字节进去，控制器就把它当作一个字符码，从字模库中取出点阵画到屏幕上。屏幕上的第 1 行对应 DDRAM 地址 0x00~0x0F，第 2 行对应 0x40~0x4F（后面的 0x10~0x27、0x50~0x67 是屏幕外的缓冲区，一般用不到）。

点一点：屏幕位置 ↔ DDRAM 地址

屏幕可见区 屏幕外缓冲区（0x10~0x27 / 0x50~0x67） 点击任意格子查看地址与设置指令
点击上方任意格子，这里会显示它的 DDRAM 地址和对应的"设置位置"指令。

地址计算公式

第 1 行 DDRAM 地址 = 0x00 + (列 - 1)     // 列 1~16
第 2 行 DDRAM 地址 = 0x40 + (列 - 1)

设置位置指令 = 0x80 | DDRAM 地址     // 指令 8（DDRAM 地址设置）

指令码的最高位 DB7 固定为 1 表示"设置 DDRAM 地址"，低 7 位就是目标地址。例如：第 2 行第 5 列 → 地址 0x44 → 指令 0xC4。

CGROM / CGRAM 是什么

CGROM（字符发生器 ROM）：出厂固化的字模表。写 0x30~0x39 显示数字 0~9，写 0x41~0x5A 显示大写 A~Z，写 0x20 是空格。对照表见项目目录里的 LCD1602字模.png。

CGRAM（字符发生器 RAM）：用户可以自定义 8 个字符（地址 0x00~0x07），用于显示中文、箭头等特殊图形。需要用"设置 CGRAM 地址"指令（0x40|addr）逐行写入 8 字节点阵数据。

判断依据屏幕显示的是字符码，不是点阵——所以想让某位置显示某个字符，只需把它的 ASCII 码写进对应 DDRAM 地址。
04

指令系统：会这 5 条就够了

HD44780 的指令集有十几条，但点亮屏幕、显示字符，绝大多数场景只需要下面 5 条。发送指令时 RS=0，发送数据时 RS=1；两者都靠 E 引脚一个"高→低"脉冲完成锁存。

指令码二进制作用执行时间
0x380011 1000功能设置：8 位数据接口、两行显示、5×7 点阵40µs
0x0C0000 1100显示开关：开显示、关光标、关闪烁（D=1 C=0 B=0）40µs
0x060000 0110输入方式：每写一个字符后地址指针自动 +1，画面不动40µs
0x010000 0001清屏：DDRAM 全部清零、地址指针归零、光标复位1.64ms
0x80 | 地址1AAA AAAA设置 DDRAM 地址（光标/写入位置），低 7 位为地址40µs
读写时序写指令：RS=0, R/W=0，数据放到 D0~D7，E 拉高 → 稍等 → E 拉低，数据在 E 的下降沿被锁存。本项目驱动在 E 高/低电平之间各延时 1ms，用"延时"代替了"忙标志检测"。

显示开关 0x0C 拆解

0x0C = 0000 1100
            └┬┘│└┬┘
             │ │  └─ B = 0  光标不闪烁
             │ └──── C = 0  不显示光标
             └────── D = 1  显示开

想显示光标就把 0x0C 改成 0x0E，想要闪烁光标改成 0x0F——这就是 0x0C 系指令的规律。

其他常用指令（了解即可）

指令码作用
0x02归位：地址指针归零，DDRAM 内容不变
0x18整屏左移一个字符位（光标不动）
0x40|addr设置 CGRAM 地址（自定义字符，0x00~0x3F）
0x10光标左移一格
0x14光标右移一格
05

初始化流程：4 条指令点亮屏幕

上电后 LCD 处于未知状态，必须先按顺序初始化。数据手册给的是"延时 → 38H → 延时 → 38H → 延时 → 38H → …"的严格流程；本项目驱动用更简洁的写法——因为每次写指令内部都延时 1ms，所以只发 4 条指令就能完成初始化。点"下一步"逐步看。

// 数据手册（SMC1602A）推荐的复位流程：
延时 15ms            // 上电稳定
写指令 0x38（不检测忙）   // 8 位、2 行、5×7
延时 5ms
写指令 0x38（不检测忙）
延时 5ms
写指令 0x38（不检测忙）
// —— 此后每次操作都需检测忙标志（STA7）或加足够延时 ——
写指令 0x38   // 功能设置
写指令 0x08   // 显示关闭
写指令 0x01   // 清屏
写指令 0x06   // 光标移动设置
写指令 0x0C   // 显示开及光标设置
为什么本驱动可以只发 4 条？因为每次写指令都自带 1ms 延时，已经满足了"两条指令之间必须等待"的要求；省去重复的 0x38 与 0x08，是因为它们的最终效果由后面的 0x0C/0x06 覆盖。新手学习时先按 4 条简化版理解，遇到个别屏不稳定再退回手册完整流程。
06

驱动代码逐块讲解

下面是本项目 Lcd1602.c 的完整逻辑，按功能拆成 5 块。驱动一共就做两件事：写指令（告诉液晶"做什么"）和写数据（告诉液晶"显示什么"），其它函数都是在这两个基础动作上封装。

① 引脚定义

sbit LCD_RS = P2 ^ 6;   // 数据/命令选择
sbit LCD_RW = P2 ^ 5;   // 读/写选择（只写，恒为 0）
sbit LCD_EN = P2 ^ 7;   // 使能脉冲
#define LCD_DataPort P0    // 8 位数据口

sbit 是 C51 的关键字，用来把某一位引脚起个名字。数据口用宏定义，之后换接线只需要改这一行。

② 写指令 / 写数据：整个驱动的核心

void LCD_WriteCommand(unsigned char command)
{
    LCD_RS = 0;            // 0 = 发送指令
    LCD_RW = 0;            // 0 = 写操作
    LCD_DataPort = command;  // 指令码放到数据线上
    LCD_EN = 1;            // E 拉高
    Delayms(1);          // 等待电平稳定
    LCD_EN = 0;            // E 拉低：下降沿锁存，指令生效
    Delayms(1);          // 给液晶执行指令的时间
}

void LCD_WriteData(unsigned char Data)
{
    LCD_RS = 1;            // 1 = 发送数据
    LCD_RW = 0;
    LCD_DataPort = Data;
    LCD_EN = 1;
    Delayms(1);
    LCD_EN = 0;        // 同样的 E 脉冲
    Delayms(1);
}

两者唯一区别就是 RS 电平：RS=0 表示这是指令，RS=1 表示这是要显示的字符数据。E 的"高 → 低"脉冲是锁存信号，两次 Delayms(1) 保证时序满足手册要求。

③ 初始化 + 设置光标位置

void LCD_Init()
{
    LCD_WriteCommand(0x38);  // 8 位、2 行、5×7
    LCD_WriteCommand(0x0c);  // 开显示、关光标
    LCD_WriteCommand(0x06);  // 写后地址自动 +1
    LCD_WriteCommand(0x01);  // 清屏
}

void LCD_SetCursor(unsigned char Line, unsigned char Column)
{
    if (Line == 1)
        LCD_WriteCommand(0x80 | (Column - 1));        // 第 1 行：0x00 起
    else
        LCD_WriteCommand(0x80 | (Column - 1) + 0x40);  // 第 2 行：0x40 起
}

注意列号从 1 开始（对人友好），内部减 1 转成 0 基地址。第 2 行整体偏移 0x40，对应第 03 节讲的地址映射：0x80 | (Column-1) + 0x40，加法优先于按位或，等价于 0x80 | ((Column-1)+0x40)。

④ 显示字符与字符串

void LCD_Showchar(unsigned char Line, unsigned char Column, unsigned char Char)
{
    LCD_SetCursor(Line, Column);   // 先定位
    LCD_WriteData(Char);           // 再写字符码
}

void LCD_ShowString(unsigned char Line, unsigned char Column, unsigned char String[])
{
    unsigned char i;
    LCD_SetCursor(Line, Column);
    for (i = 0; String[i] != 0; i++)   // 遇 '\0' 结束
        LCD_WriteData(String[i]);              // 地址自动 +1，字符从左往右排开
}

字符串以 \0 结尾，所以 String[i] != 0 就是"还没写完"的判断。因为初始化设了 0x06（地址自动 +1），连续写数据就会自动往右走。

⑤ 显示数字：先把数拆成单个字符

int LCD_Pow(int X, int Y)   // 自己实现的 X 的 Y 次方
{
    unsigned char i;
    int Result = 1;
    for (i = 0; i < Y; i++) Result *= X;
    return Result;
}

void LCD_ShowNum(unsigned char Line, unsigned char Column,
                 unsigned char Number, int Length)
{
    unsigned char i;
    LCD_SetCursor(Line, Column);
    for (i = Length; i > 0; i--)
        // 逐位取出数字，加 0x30 转成 ASCII 码后写入
        LCD_WriteData(0x30 + Number / LCD_Pow(10, i - 1) % 10);
}

数字 66 在屏幕上显示的是字符 '6' 和 '6'，它们的 ASCII 码正好是 0x30+6=0x36。所以先把 66 拆成十位 6、个位 6，再各加 0x30 写进去。Length 表示显示几位（不足高位补 0）。

同理封装：LCD_ShowSignedNum 先写 '+'/'-' 再显示绝对值；LCD_ShowHexNum 按 16 进制拆位（大于 9 补 'A'~'F'）；LCD_ShowBinNumber 按 2 进制拆位。

本项目的一个隐藏"地雷"（建议改掉）Lcd1602.h 里声明的是 LCD_ShowNum(Line, Column, Length, Number)（长度在前），而 Lcd1602.c 里定义的是 LCD_ShowNum(Line, Column, Number, Length)（数字在前）。C 语言不检查形参名字，所以能编译通过，main.c 里 LCD_ShowNum(1,1,66,2) 恰好"数字=66、长度=2"结果正确；但如果按头文件理解去调用 LCD_ShowNum(1,1,2,66)，就会变成"数字=2、长度=66"直接出错。建议把 .c 和 .h 的参数顺序统一（推荐：长度在数字前面）。

使用示例：跑一遍 main.c

项目的 main.c 只做了三件事：初始化，然后调 6 个显示函数。下面用虚拟屏模拟器还原它的真实效果——点任意一个函数芯片，看它写进屏幕哪个位置。

main.c 原始代码

#include "Lcd1602.h"
#include <STC89C5xRC.H>
void main()
{
    LCD_Init();                       // ① 初始化
    LCD_ShowString(2, 3, "xmy");        // ② 第2行第3列起显示字符串
    LCD_ShowNum(1, 1, 66, 2);          // 数字 66
    LCD_ShowSignedNum(1, 4, -33, 2);    // 带符号 -33
    LCD_ShowHexNum(1, 10, 0xa5, 2);   // 十六进制 A5
    LCD_ShowBinNumber(2, 6, 0xa5, 8); // 二进制 10100101
    LCD_Showchar(2, 14, 0xdf);         // 特殊字符（°）
    while (1) { }                   // 保持显示
}

08

常见问题排查清单

屏幕全暗，什么都没有

① 对比度：VL 电位器没调好是头号原因，慢慢旋转到出现黑影；② 检查 VSS/VDD 是否接反或虚焊；③ 检查是否执行了 0x0C（开显示）。

屏幕亮但全是方块/花屏

初始化时序不对，或数据口接错位（如 D0~D7 接反）。对照第 05 节流程重新初始化，检查 P0.0~P0.7 与 D0~D7 一一对应。

只有一排方块，没有字符

对比度过强（方块全黑）或过弱（字符看不见）。调整 VL 电位器，让字符清晰、背景干净。

显示内容乱跳 / 重复

两条指令之间延时不够，液晶没执行完就被打断。把写指令/写数据里的 Delayms 加大，或改用忙标志检测（读 STA7）。

想显示中文/箭头

CGROM 没有中文字模。用 CGRAM 自定义字符：先把 5×8 点阵数据按行写入 CGRAM 地址（0x40|addr），再在 DDRAM 里写 0x00~0x07 引用它，最多 8 个。

显示错位，内容跑到第二行

第 1 行显示超 16 个字符就会溢出到第 2 行（地址 0x0F 之后是 0x40 区）。字符串按行长度 16 截断，或写满 16 个后换行显示。
