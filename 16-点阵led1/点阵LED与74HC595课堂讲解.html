89C52 · 8×8 点阵 · 74HC595

3 根线，点亮 64 个 LED

8×8 点阵直接驱动要 16 根 IO，单片机根本不够用。74HC595 是「串行输入、并行输出」的移位寄存器：用 3 根线（数据、移位、锁存）控制 8 个输出，还能一片接一片级联。下面的动画会一步步演示数据是怎么"排队进去、一起出来"的。

74HC595 核心概念 串行进：SER 一位一位进 并行出：Q0~Q7 一次全给

一句话原理：数据从 SER 每次进 1 位（移位寄存器里排队），移满 8 位后，给 RCLK 一个脉冲，8 位数据一次性同时出现在 Q0~Q7 上——就像 8 个人排队进门，站齐了才一起喊"稍息"。

74HC595 是什么：串入并出

全名「8 位串行输入 / 并行输出移位寄存器」：输入侧只有 1 根数据线，输出侧却有 8 根。用时间换 IO。

为什么要它

方案需要的 IO
8×8 点阵直连8 行 + 8 列 = 16 根，89C52 全用光
用 1 片 74HC595SER + SRCLK + RCLK = 3 根（+ P0 管另一维 8 根）
再级联 1 片仍 3 根，多 8 个输出（Q7' 接下一片）
这是「移位寄存器」类芯片的典型价值：数据慢点进（一位一位），输出却能很多（一片 8 位，可无限级联）。

三个关键引脚，三根控制线

引脚作用（一个词记住）
SER串行数据输入——进，每次 1 位
SRCLK移位时钟——走，上升沿移进 1 位
RCLK锁存时钟——停，上升沿把 8 位一次送到输出
还有两个常接死的脚：OE（输出使能，低有效，接地常开）、SRCLR（移位清零，低有效，接高常开）。

OE 是低有效，最容易踩坑：高电平时 8 个输出全部被强制关闭，怎么送数都不亮。开发板上 OE 一般直接接地（常开），如果点阵不亮，先量一下 OE 是不是低电平。

核心：数据怎么"排队进去、一起出来"

以"把 0x01 送到输出"为例：0x01 的 8 个位是 0000 0001（Q0 亮，其余灭）。按先送最高位的顺序，SER 依次给 0,0,0,0,0,0,0,1，每来一个 SRCLK 上升沿移进一格；8 个脉冲后，RCLK 上升沿，Q0~Q7 一次性输出。

移位演示 数据 0x01 已移位 0 / 8
SER 0 当前要送的位 移位寄存器（进一位，全体右移一格）
SRCLK 移位脉冲（上升沿移一位） 锁存后输出（Q0~Q7 同时更新）
RCLK 移位满 8 位后，点"锁存"把数据一次送出
预设数据
观察：8 个 SRCLK 之后，移位寄存器里正好是 0000 0001，点"锁存"，Q0 亮起。注意送数顺序是先送最高位（bit7 → bit0）。

时序怎么写在代码里

一次"送 1 位"= 三步：把 SER 置成要送的位 → SRCLK 给一个脉冲（1 再 0）→ 数据进一格。

// 送一个字节 0x01（bit7 到 bit0，共 8 位）
for (i = 0; i < 8; i++)
{
    SER = (data >> (7 - i)) & 0x01;   // ① 取当前位放到数据线
    SRCLK = 1;                       // ② 移位时钟上升沿
    SRCLK = 0;                       //    拉回低电平，准备下一个脉冲
}
RCLK = 1;                           // ③ 锁存：8 位一次输出
RCLK = 0;
两个时钟都要"1 再 0"给完整脉冲——上升沿（0→1）才触发动作，只拉高不拉低，下一个脉冲就没了。这是写驱动最常见的错。

8×8 点阵：同一时刻只亮一行

64 个 LED 排成 8 行 8 列。硬件上不可能让 64 个同时受控（IO 不够），所以用逐行扫描：同一时刻只点亮一行，8 行飞快地轮流亮，靠人眼视觉暂留拼出完整画面。

工程代码逐行讲解

对照工程 src/Int/Int_MatrixLED.c 和 src/main.c。

引脚定义

// 74HC595 的三根控制线接到 P3.4 / P3.5 / P3.6
#define SRE   P34    // 数据/使能线：接 595 哪个功能脚（SER 或 OE），看原理图
#define RCLK  P35    // 锁存时钟 → 595.RCLK（上升沿把 8 位送到输出）
#define SRCLK P36    // 移位时钟 → 595.SRCLK（上升沿移入 1 位）
SRE 这个名字和接法要看开发板：不同板子对 P3.4 这根线的称呼不同（有的接 595 的 SER，有的接 OE）。上课前先确认 J24 跳线帽插好、对照模块原理图看 P3.4/P3.5/P3.6 分别进了 595 的哪个脚——代码逻辑一样，硬件接法决定现象。

显示缓冲区与设置图案

// main.c：8 个字节 = 8 行，每行 1 位为 1（取反后是 0 = 点亮）
u8 pic[8] = { 0x01, 0x02, 0x04, 0x08,
              0x10, 0x20, 0x40, 0x80 };
Int_MatrixLED_SetPic(pic);   // 拷进显示缓冲区

// Int_MatrixLED.c：把图案存进 s_led_buff
static u8 s_led_buff[8];      // 显示缓冲区：8 行 × 8 位
void Int_MatrixLED_SetPic(u8 *pic)
{
    u8 i;
    for(i=0;i<8;i++){ s_led_buff[i] = pic[i]; }
}
工程原文件写的是 static s_led_buff[8]; —— 缺了类型，SDCC 默认按 int（16 位）处理，功能碰巧对。建议写成 static u8 s_led_buff[8];。

Refresh：逐行扫描的五步节奏

步代码动作为什么
①P0 = 0xff;全部行关闭消隐，防止换行瞬间拖影
②RCLK = 1; RCLK = 0;锁存脉冲把 595 里已移入的数据一次输出
③P0 = ~s_led_buff[i];选中第 i 行该行要亮的列是 0（低电平点亮）
④SRCLK = 1; SRCLK = 0;移位脉冲让 595 接收这一行的数据
⑤Delayms(1);保持 1ms视觉暂留，然后扫下一行
void Int_MatrixLED_Refresh()
{
    u8 i;
    SRE = 1; SRCLK = 1; SRCLK = 0; SRE = 0;  // 开场动作（作用看原理图）
    for(i=0;i<8;i++){
        P0 = 0xff;              // ① 关行消隐
        RCLK = 1; RCLK = 0;    // ② 锁存输出
        P0 = ~s_led_buff[i];     // ③ 选中第 i 行
        SRCLK = 1; SRCLK = 0; // ④ 移位脉冲
        Delayms(1);            // ⑤ 保持 1ms
    }                            // 8 行扫完 = 8ms 一帧 ≈ 125Hz
}
主程序里就是死循环刷：while(1){ Int_MatrixLED_Refresh(); }，靠不断重扫维持画面；改 s_led_buff 里的 8 个字节，画面就变。

一片不够？Q7' 级联扩展

595 的 9 脚 Q7' 是"移位寄存器最右一位"的串行输出：数据从右边掉出来时，把它接到下一片的 SER，就能一片接一片，IO 始终只有 3 根。

MCU SER / SRCLK / RCLK 第1片 595 Q7' → SER 第2片 595 Q7' → … N 片 = 8×N 输出 
// 两片级联送 16 位：先送第 2 片的数据（高 8 位），再送第 1 片（低 8 位）
for(i=0;i<16;i++){
    SER = (data16 >> (15-i)) & 0x01;
    SRCLK = 1; SRCLK = 0;
}
RCLK = 1; RCLK = 0;   // 两片一起锁存，输出同时更新
应用：2 片 → 8×16 点阵 / 16 位数码管段选；更多片 → 大屏。唯一代价是送数时间变长，但每片只需 8 个脉冲，速度足够。

上课必讲的 8 个坑

① OE 低有效
13 脚 OE 高电平 = 输出全关，怎么送数都不亮。不亮先量 OE 是不是低电平（开发板一般接地）。
② 时钟要给完整脉冲
SRCLK / RCLK 都是上升沿触发，必须"1 再 0"。只拉高不拉回低，下一个脉冲不触发。
③ 移满 8 位再锁存
边移边锁存 = 显示错乱。8 个 SRCLK 之后才给 RCLK。
④ 送数顺序要统一
本页演示先送最高位（bit7→bit0）；代码里取位写法要和它一致，混用会左右反/上下反。
⑤ 换行要消隐
切换行瞬间把行全关（P0 = 0xff）再送新行，否则有拖影。
⑥ 刷新率要够高
8 行 × 1ms = 8ms/帧 ≈ 125Hz 不闪；低于 50Hz 人眼能看出闪烁。
⑦ 级联数脉冲
N 片就要送 8×N 个 SRCLK 脉冲，再统一锁存；少送一位，输出整体错位。
⑧ 非法注释与缺类型
#点阵刷新 不是合法注释——# 会被当成预处理指令，Keil C51 报 WARNING C314（bad #directive syntax），不中断编译，但仍是错的，应写 //；s_led_buff 缺类型建议补 u8。
