# I²C 使用与时序总结

## 1. I²C 基本概念

I²C 总线使用两根信号线：

- `SCL`：时钟线，由主机产生时钟。
- `SDA`：数据线，用于双向传输数据。

SCL 和 SDA 都需要上拉电阻。总线空闲时，两根线都应保持高电平。

I²C 通信通常由以下部分组成：

1. 起始条件（Start）
2. 发送器件地址和读写位
3. 接收 ACK
4. 发送或接收数据
5. 每个字节后的 ACK/NACK
6. 停止条件（Stop）

## 2. 最重要的时序规则

### 2.1 SDA 只能在 SCL 低电平时改变

普通数据传输期间：

- SCL 为低电平时，可以改变 SDA。
- SCL 为高电平时，SDA 必须保持稳定。
- 接收方通常在 SCL 高电平期间读取 SDA。

如果在 SCL 高电平期间改变 SDA，可能被识别为起始条件或停止条件。

### 2.2 起始条件

总线空闲时，SCL 和 SDA 均为高电平。保持 SCL 为高电平，让 SDA 从高电平变为低电平，即产生起始条件。

```text
SCL: ─────────高─────────
SDA: ─────高─────\____低__
                 Start
```

对应操作顺序：

```c
SDA = 1;
SCL = 1;
SDA = 0;
SCL = 0;
```

最后将 SCL 拉低，为发送第一个数据位做准备。

### 2.3 停止条件

先让 SDA 为低电平，再保持 SCL 为高电平，让 SDA 从低电平变为高电平，即产生停止条件。

```text
SCL: ─────────高─────────
SDA: _____低_____/────高──
                 Stop
```

对应操作顺序：

```c
SDA = 0;
SCL = 1;
SDA = 1;
```

### 2.4 发送一个数据位

发送每一位时应遵循：

1. SCL 为低电平。
2. 设置 SDA 数据。
3. 将 SCL 拉高，使接收方读取数据。
4. 将 SCL 拉低，结束当前时钟。

```c
SCL = 0;
SDA = bit;
SCL = 1;
SCL = 0;
```

### 2.5 发送一个字节

I²C 每个字节为 8 位，按最高位到最低位发送，即先发送 bit7，最后发送 bit0。每发送完一个字节，还需要第九个时钟处理 ACK。

```text
时钟序号：  1  2  3  4  5  6  7  8 | 9
传输内容： b7 b6 b5 b4 b3 b2 b1 b0 | ACK
```

## 3. ACK 和 NACK 时序

### 3.1 ACK 的含义

每传输完 8 位数据，发送方必须释放 SDA，由接收方在第九个时钟返回应答：

- `SDA = 0`：ACK，表示成功接收。
- `SDA = 1`：NACK，表示未应答或结束接收。

### 3.2 主机接收 ACK

主机发送完一个字节后：

1. 将 SCL 拉低。
2. 向 SDA 写 1，释放 SDA。
3. 将 SCL 拉高。
4. 读取 SDA。
5. 将 SCL 拉低，结束第九个时钟。

```c
SCL = 0;
SDA = 1;
SCL = 1;
AckBit = SDA;
SCL = 0;
```

最后一步不能省略。若读取 ACK 后 SCL 仍保持高电平，下一次改变 SDA 会违反“SDA 只能在 SCL 低电平时改变”的规则，而且第九个时钟没有完整结束。

### 3.3 主机发送 ACK/NACK

主机读取完从机发来的一个字节后，需要在第九个时钟回复：

```c
SCL = 0;
SDA = AckBit;  // 0 为 ACK，1 为 NACK
SCL = 1;
SCL = 0;
SDA = 1;       // 释放 SDA
```

- 后面还要继续读取数据：发送 ACK。
- 当前是最后一个字节：发送 NACK，然后产生停止条件。

## 4. 接收一个字节

主机接收数据前应向 SDA 写 1，释放 SDA，让从机控制数据线。每接收一位时：

1. SCL 保持低电平，从机准备数据。
2. 主机将 SCL 拉高。
3. 主机在 SCL 高电平期间读取 SDA。
4. 主机将 SCL 拉低。

```c
SDA = 1;
for (i = 0; i < 8; i++)
{
    SCL = 1;
    Byte <<= 1;
    if (SDA)
    {
        Byte |= 0x01;
    }
    SCL = 0;
}
```

## 5. 常见通信流程

### 5.1 主机向从机写数据

```text
Start
→ 器件地址 + 写位0
→ 等待ACK
→ 数据或存储地址
→ 等待ACK
→ 数据
→ 等待ACK
→ Stop
```

每次发送一个字节后都必须检查 ACK。未收到 ACK 时，不应继续正常发送。

### 5.2 主机从从机读数据

```text
Start
→ 器件地址 + 读位1
→ 等待ACK
→ 接收数据
→ 主机发送NACK
→ Stop
```

如果连续读取多个字节：

- 除最后一个字节外，每个字节后主机都发送 ACK。
- 最后一个字节后主机发送 NACK，再发送 Stop。

### 5.3 AT24C02 随机读取

```text
Start
→ 器件地址 + 写位0
→ ACK
→ 存储地址
→ ACK
→ Repeated Start
→ 器件地址 + 读位1
→ ACK
→ 接收数据
→ NACK
→ Stop
```

Repeated Start 是不先发送 Stop，直接再次产生 Start，可保持对总线的控制。

## 6. C51 软件模拟 I²C 的注意事项

### 6.1 释放 SDA

8051 准双向口通常通过向端口写 1 来释放 SDA：

```c
SDA = 1;
```

这不是主动输出强高电平，而是让外部上拉电阻将 SDA 拉高，并允许从机把 SDA 拉低。SDA、SCL 必须有合适的外部上拉电阻。

### 6.2 是否必须添加延时

C51 指令执行本身需要时间，所以低主频、12T 内核的软件 I²C 有时不加显式延时也能工作。但不能仅凭“C51 较慢”判断一定满足时序，还应考虑：

- 单片机是 12T、6T 还是 1T 内核。
- 晶振频率。
- 编译器优化后的实际指令数量。
- 从机支持的最高 I²C 频率。
- 上拉电阻和总线电容造成的上升时间。

标准模式 100 kHz 常见最低时序要求如下，最终以所用器件数据手册为准：

| 参数 | 含义 | 最小值 |
|---|---|---:|
| `tLOW` | SCL 低电平时间 | 4.7 μs |
| `tHIGH` | SCL 高电平时间 | 4.0 μs |
| `tSU:STA` | 起始条件建立时间 | 4.7 μs |
| `tHD:STA` | 起始条件保持时间 | 4.0 μs |
| `tSU:DAT` | 数据建立时间 | 250 ns |
| `tSU:STO` | 停止条件建立时间 | 4.0 μs |
| `tBUF` | 停止到下一次起始的空闲时间 | 4.7 μs |

如果单片机速度较快，应加入短延时，并用示波器或逻辑分析仪测量 SCL 的高、低电平时间。

### 6.3 软件模拟时序检查口诀

```text
空闲双高；SCL低时改数据；SCL高时读数据；
高时SDA下降是Start；高时SDA上升是Stop；
八位数据加一位应答；每个时钟必须有完整高低电平。
```

## 7. AT24C02 额外注意事项

- 常见 7 位器件地址为 `0x50`，8 位写地址常写作 `0xA0`，读地址常写作 `0xA1`；具体地址还受 A0、A1、A2 引脚影响。
- 写入后芯片需要内部写周期，不能立即进行下一次普通读写。
- 可以固定延时等待写入完成，也可以反复发送器件地址进行 ACK 查询。
- 页写不能跨越器件规定的页边界，否则地址可能在当前页内回卷。
- AT24C02 的内部存储地址通常为 1 字节，其他容量型号可能使用不同地址宽度。

## 8. 调用函数时的基本顺序

写入时可按以下顺序理解：

```text
I2C_Start()
I2C_SendByte(器件写地址)
I2C_ReceiveAck()
I2C_SendByte(存储地址)
I2C_ReceiveAck()
I2C_SendByte(数据)
I2C_ReceiveAck()
I2C_Stop()
```

读取最后一个字节时：

```text
I2C_Receive_Byte()
I2C_SendAck(1)     // NACK，表示不再继续读取
I2C_Stop()
```

判断软件 I²C 是否正确时，不仅要看最终读写结果，还应检查每一个 SCL 周期是否完整，以及 SDA 是否只在允许的时间改变。
