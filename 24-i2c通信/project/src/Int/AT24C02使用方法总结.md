# AT24C02 使用方法总结

## 1. AT24C02 是什么

AT24C02 是一款使用 I²C 总线通信的 EEPROM：

- 掉电后数据不会丢失。
- 总容量为 2 Kbit，即 256 Byte。
- 内部地址范围为 `0x00~0xFF`。
- 每个地址保存 1 Byte 数据，即 `0x00~0xFF`。
- 常用于保存设置、计数值、校准参数等少量数据。

## 2. 硬件连接

当前工程的软件 I²C 引脚为：

| AT24C02 引脚 | 连接 |
|---|---|
| SDA | 单片机 P2.0 |
| SCL | 单片机 P2.1 |
| VCC | 电源正极 |
| GND | 电源地 |
| WP | 接地时允许写入；接高电平时禁止写入 |
| A0、A1、A2 | 接地时使用当前代码中的默认器件地址 |

SDA 和 SCL 是开漏/准双向通信线，需要上拉电阻。常见上拉阻值为 `4.7kΩ~10kΩ`，实际值应结合电压、总线长度和电容确定。

## 3. 器件地址

当前代码使用：

```c
#define AT24C02_ADDRESS 0xA0
```

这里的 `0xA0` 是已经包含读写位的 8 位写地址：

```text
写地址：0xA0，最低位为 0
读地址：0xA1，最低位为 1
```

所以读取时可以写成：

```c
I2C_SendByte(AT24C02_ADDRESS | 0x01);
```

若 A0、A1、A2 没有全部接地，器件地址会发生变化，必须根据硬件接线修改地址。

## 4. 写入一个字节

当前接口：

```c
AT24C02_WriteByte(WordAddress, Data);
```

参数含义：

- `WordAddress`：AT24C02 内部存储地址，范围为 `0x00~0xFF`。
- `Data`：要保存的一个字节，范围为 `0x00~0xFF`。

调用示例：

```c
AT24C02_WriteByte(0x10, 123);
```

这表示把十进制数 `123` 保存到内部地址 `0x10`。

单字节写入时序：

```text
Start
→ 发送器件写地址 0xA0
→ 接收 ACK
→ 发送内部存储地址 WordAddress
→ 接收 ACK
→ 发送数据 Data
→ 接收 ACK
→ Stop
→ 等待内部写入完成
```

每个字节发送完后，从机应在第九个时钟返回 ACK：

- ACK 为 `0`：器件已应答。
- ACK 为 `1`：器件未应答，可能是地址错误、接线错误或器件正处于写周期。

## 5. 写周期等待

执行 `I2C_Stop()` 后，AT24C02 还需要把数据真正写入 EEPROM。在内部写周期完成之前，芯片通常不会正常响应下一次访问。

因此，写入后必须采用一种等待方式：

### 方法一：固定延时

```c
AT24C02_WriteByte(0x10, 123);
Delayms(5);
```

具体最长写入时间以所用芯片的数据手册为准。固定延时简单，但可能等待过久或等待不足。

### 方法二：ACK 查询

反复发送器件写地址，直到收到 ACK，表示内部写周期已经结束。这种方式更可靠，也不必固定等待完整的最长时间。

当前 `AT24C02_WriteByte()` 在发送 Stop 后没有等待写周期，因此应用层连续写入或立即读取时，需要额外处理写周期。

## 6. 读取一个字节

当前接口：

```c
Data = AT24C02_ReadByte(WordAddress);
```

调用示例：

```c
unsigned char value;

value = AT24C02_ReadByte(0x10);
```

随机读取时序：

```text
Start
→ 发送器件写地址 0xA0
→ 接收 ACK
→ 发送要读取的内部地址 WordAddress
→ 接收 ACK
→ Repeated Start
→ 发送器件读地址 0xA1
→ 接收 ACK
→ 接收一个字节
→ 主机发送 NACK
→ Stop
```

前半段使用写地址并不是在写数据，而是在告诉 AT24C02 接下来要读取哪个内部地址。

发送完内部地址后再次产生 Start，称为重复起始条件（Repeated Start）。随后发送读地址 `0xA1`，AT24C02 才开始向主机发送数据。

读取最后一个字节后调用：

```c
I2C_SendAck(1);
```

这里的 `1` 表示 NACK，通知 AT24C02 主机不再继续读取，然后产生 Stop 结束通信。

## 7. ACK 与 NACK

ACK/NACK 是 I²C 的应答位：

| SDA 电平 | 含义 |
|---|---|
| 0 | ACK，继续通信 |
| 1 | NACK，未应答或结束读取 |

写入过程中，主机发送一个字节后释放 SDA，由 AT24C02返回 ACK。

读取过程中，AT24C02 发送一个字节后，由主机返回 ACK 或 NACK：

- 还要继续读取下一个字节：主机发送 ACK，即 `0`。
- 已经读取最后一个字节：主机发送 NACK，即 `1`。

## 8. 页写注意事项

AT24C02 支持一次写入多个字节，但页写不能随意跨页。常见 AT24C02 每页为 8 Byte，最终应以具体芯片数据手册为准。

例如一页为 8 Byte 时：

```text
第0页：0x00~0x07
第1页：0x08~0x0F
第2页：0x10~0x17
```

如果从 `0x06` 开始连续写入多个字节并越过 `0x07`，地址可能在当前页内回卷，覆盖前面的数据。

当前工程只实现单字节写入，不存在一次调用跨页的问题；如果以后增加数组写入接口，就必须拆分页写入，并在每一页写完后等待写周期结束。

## 9. 数据范围与数据类型

AT24C02 的每个地址只能保存一个字节：

```text
unsigned char：0~255
```

如果要保存 `unsigned int`、`long` 或结构体，需要拆成多个字节写入，并在读取后重新组合。同时需要明确字节顺序，避免换芯片或换编译器后数据格式不一致。

## 10. 当前工程的基本调用示例

```c
#include "Int_AT24c02.h"
#include "Com_util.h"

void main(void)
{
    unsigned char value;

    /* 把 123 写入 0x10。 */
    AT24C02_WriteByte(0x10, 123);

    /* 等待 EEPROM 内部写周期结束，时间以芯片手册为准。 */
    Delayms(5);

    /* 从同一地址读取数据，正常情况下 value 等于 123。 */
    value = AT24C02_ReadByte(0x10);

    while (1)
    {
    }
}
```

## 11. 当前代码使用时需要注意

1. `AT24C02_WriteByte()` 中声明的 `Ack` 没有使用，可以删除，或者用于保存并检查 ACK。
2. `Data` 参数应明确声明为 `unsigned char`，让接口含义清楚并避免依赖旧式 C 的隐式类型规则。
3. 当前代码虽然调用了 `I2C_ReceiveAck()`，但没有判断返回值，因此器件未应答时程序仍会继续执行。
4. 写入函数结束后没有等待内部写周期，连续操作时需要在应用层延时或增加 ACK 查询。
5. WP 必须为低电平才能写入；WP 为高电平时通常仍可读取，但无法写入。
6. 断电不能发生在 EEPROM 内部写周期中，否则正在写入的数据可能不可靠。
7. EEPROM 有写入寿命限制，不适合在高速循环中反复写同一个地址。

## 12. 排查通信失败的方法

若读出的数据不正确，可按以下顺序检查：

1. 检查 VCC、GND、SDA、SCL、WP、A0、A1、A2 接线。
2. 检查 SDA 和 SCL 是否有上拉电阻。
3. 检查器件地址是否与 A0、A1、A2 接线一致。
4. 检查每次发送器件地址和数据后是否收到 ACK。
5. 检查写入后是否等待内部写周期完成。
6. 使用逻辑分析仪观察 Start、地址、ACK、数据、NACK 和 Stop。
7. 先固定写入一个简单数值，例如 `0x55`，再从同一地址读取进行验证。

## 13. 记忆口诀

```text
写数据：起始、写地址、字地址、数据、停止、等写完。
读数据：先写字地址、重复起始、切换读地址、读数据、回 NACK、停止。
一字节八位，第九位应答；低为 ACK，高为 NACK。
```
