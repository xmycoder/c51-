## 1. DS1302 是什么

DS1302 是 Dallas/Maxim（现 Analog Devices）推出的**涓流充电型实时时钟芯片**。它解决的核心问题是：单片机断电后变量全部丢失，而 DS1302 自带电池输入，可以让时间在主电源断开后继续走。

它的能力（数据手册第 1 页）：

| 特性 | 说明 |
|---|---|
| 计时内容 | 秒、分、时、日、月、星期、年，含闰年补偿（有效期到 2100 年） |
| 掉电 RAM | 31 × 8 字节电池备份静态 RAM |
| 接口 | 3 线串行接口（CE / I/O / SCLK），TTL 兼容（VCC = 5V 时） |
| 传输方式 | 单字节或突发（Burst）模式，读/写均可 |
| 供电 | 2.0V ~ 5.5V 全功能工作 |
| 功耗 | 2.0V 电池备份下维持走时电流 < 300nA；CH=1 停振时 < 100nA |
| 涓流充电 | 可对可充电电池/超级电容涓流充电（可选功能） |
| 温度 | 民用 0~70°C；型号带 N 后缀为工业级 -40~85°C |

一句话理解：**DS1302 = 一个用电池供着电、一直在走字的电子表，单片机通过 3 根线随时去"看表"和"对表"。**

## 2. 硬件连接

### 2.1 引脚定义（数据手册第 4 页）

| 引脚 | 名称 | 方向 | 功能 |
|---|---|---|---|
| 1 | VCC2 | 电源 | 双电源配置时的主电源 |
| 2 | X1 | — | 32.768kHz 晶振 |
| 3 | X2 | — | 32.768kHz 晶振 |
| 4 | GND | 电源 | 地 |
| 5 | CE | 输入 | 片选/传输使能，高电平有效（旧版手册叫 RST，功能相同） |
| 6 | I/O | 双向 | 数据线（输入/**推挽输出**） |
| 7 | SCLK | 输入 | 串行时钟 |
| 8 | VCC1 | 电源 | 电池备份/单电源供电 |

三个要点：

- **CE、SCLK、I/O 三个引脚内部都有约 40kΩ 的对地下拉电阻**，悬空时自动为低，不会误触发。
- **I/O 是推挽输出**（不是开漏），所以总线上**不需要**外部上拉电阻。
- 电源切换规则：当 VCC2 > VCC1 + 0.2V 时由 VCC2 供电，否则由 VCC1 供电。

### 2.2 与 51 单片机的典型接线

本工程使用的接线（与江协科技开发板一致）：

```
   STC89C52                    DS1302
  ┌─────────┐    SCLK   ┌──────────┐
  │     P3.6├───────────┤7 SCLK    │        VCC2 (5V)──┤1
  │         │           │          │        VCC1 (3V 纽扣电池)──┤8
  │     P3.4├───────────┤6 I/O     │
  │         │           │          │   X1 ── 32.768kHz 晶振 ── X2
  │     P3.5├───────────┤5 CE      │   （直接接 2、3 脚，不需外部电容）
  │         │           │          │
  │      GND├───────────┤4 GND     │
  └─────────┘           └──────────┘
```

对应代码里的引脚定义：

```c
sbit DS1302_SCLK = P3 ^ 6;  // 串行时钟
sbit DS1302_IO   = P3 ^ 4;  // 双向数据
sbit DS1302_CE   = P3 ^ 5;  // 使能
```

### 2.3 晶振（数据手册第 5 页）

- 必须用 **32.768kHz**、负载电容 **CL = 6pF** 的表晶，内部振荡器**不需要**任何外部电阻电容。
- 正常情况下起振时间小于 1 秒。
- 布局上晶振要尽量贴近芯片、远离高频信号线（手册图 2 给出了推荐布局）。
- **注意**：示波器探头直接点 X1/X2 会改变负载电容甚至使晶振停振，调试时不要直接测这两个脚。

### 2.4 上电的一个小细节

手册第 6 页要求："上电时，在 VCC 超过 2.0V 之前 CE 必须保持低电平"。而 51 复位后所有口线都是高电平（CE 被拉高）。好在只要不发 SCLK 脉冲，芯片不会有任何动作，而 `DS1302_Init()` 会第一时间把 CE、SCLK 归零——所以**main 里要尽早调用 `DS1302_Init()`**，不要在它之前塞一大段代码。

## 3. 三线接口的工作方式

一次数据传输由 **CE 的上升沿启动**，由 **CE 拉低结束**。CE 一旦拉低，传输立即终止、I/O 立即变高阻态。CE 高电平期间，数据在 SCLK 的节拍下逐位移入/移出。

5 条必须记住的规则（全部来自手册第 5、6 页原文）：

1. **所有字节都从最低位（bit0）开始移位。** 这是 DS1302 和常见 SPI 器件（通常高位在前）最大的不同，自己写驱动时最容易搞反。
2. **主机向芯片写**：数据必须在 SCLK **上升沿**时有效，并且在 SCLK 为高的整个期间保持不变。也就是说：先把数据放到 I/O 上，再制造上升沿。
3. **芯片向主机读**：数据在 SCLK **下降沿**之后更新。手册原话："第一个数据位在命令字节最后一位写入之后的第一个下降沿出现"——这句是读时序的灵魂，6.3 节详细展开。
4. **CE 拉高之前 SCLK 必须为低电平**（手册第 6 页原文）。本工程所有函数进出时都保证 SCLK 停在 0。
5. 读的过程中，**每个 SCLK 上升沿芯片都会把 I/O 短暂置为高阻**，下降沿再重新驱动（手册第 6 页"DATA OUTPUT"一节的注释）。所以采样点固定放在下降沿之后最稳妥。

另外两个实用细节：

- **写**：多余的 SCLK 脉冲会被芯片忽略（16 个上升沿之后多给的时钟不算数）。
- **读**：CE 保持高的情况下多给 SCLK，芯片会**重复输出数据字节**——这正是突发连续读的实现原理。

## 4. 命令字节

每一次传输都以一个**命令字节**开头（LSB 先发）。它告诉 DS1302：访问哪个寄存器、是读还是写（手册第 5 页图 3）：

| 位 | 名称 | 含义 |
|---|---|---|
| bit7 | 固定 1 | **必须为 1**；若为 0，对芯片的一切写操作被禁止 |
| bit6 | RAM/CK | 0 = 时钟/日历寄存器，1 = RAM |
| bit5~bit1 | A4~A0 | 寄存器地址（0~31） |
| bit0 | RD/WR | 0 = 写（主机→芯片），1 = 读（芯片→主机） |

推导两个例子（以秒寄存器为例，地址 0）：

```
写秒： 1 0 00000 0  →  1000 0000 = 0x80
读秒： 1 0 00000 1  →  1000 0001 = 0x81
```

规律：**写命令 = 0x80 | (地址 << 1)，读命令 = 写命令 + 1。** RAM 则把 bit6 也置 1：写 RAM 第 n 字节 = 0xC0 | (n << 1)。

## 5. 内部寄存器详解

### 5.1 时钟/日历寄存器（手册第 9 页 Table 3）

| 写命令 | 读命令 | 寄存器 | bit7 | bit6 | bit5 | bit4 | bit3~0 | 取值范围 |
|---|---|---|---|---|---|---|---|---|
| 80h | 81h | 秒 | **CH** | 秒十位(0-5) ←bit6~4 | | | 秒个位(0-9) | 00–59 |
| 82h | 83h | 分 | 0 | 分十位(0-5) ←bit6~4 | | | 分个位(0-9) | 00–59 |
| 84h | 85h | 时 | 12/24 | 见 5.3 节 | | | 时个位(0-9) | 1–12 / 0–23 |
| 86h | 87h | 日 | 0 | 0 | 日十位(0-3) ←bit5~4 | | 日个位(0-9) | 01–31 |
| 88h | 89h | 月 | 0 | 0 | 0 | 月十位(0-1) | 月个位(0-9) | 01–12 |
| 8Ah | 8Bh | 星期 | 0 | 0 | 0 | 0 | 星期(1-7) | 01–07 |
| 8Ch | 8Dh | 年 | 年十位(0-9) ←bit7~4 | | | | 年个位(0-9) | 00–99 |

注意三点：

- **所有时间寄存器存的是 BCD 码**（例如 59 秒存成 0x59，即 0101 1001），不是二进制。这是显示乱码的头号来源，见 8.1 节。
- 星期寄存器的编码是**用户自定义**的，只要 1~7 顺序递增即可（比如自己规定 1 = 星期日）。
- 非法的日期（比如 2 月 30 日）会导致未定义行为，设时间时要保证数据合法。

### 5.2 CH 位：时钟停振标志（手册第 7 页）

秒寄存器的 bit7 是 **CH（Clock Halt）**：

- CH = 1：振荡器停振，芯片进入低功耗待机（电流 < 100nA），**时间不走**；
- CH = 0：时钟运行；
- **上电初始状态不确定**（手册原文 "The initial power-on state is not defined"）。

这就是"新芯片时间不走"的常见原因。写秒寄存器时把这一位一起清掉即可：比如设 55 秒，写入 `0x00 | 0x55 = 0x55`（bit7 自然为 0）。

### 5.3 小时寄存器与 12/24 小时制（手册第 6 页）

小时寄存器 bit7 是模式选择位：

| 模式 | bit7 | bit5 | bit4 | 例子 |
|---|---|---|---|---|
| 24 小时制 | 0 | 时十位的高位（20~23 点时为 1） | 时十位 | 23 点 → 0x23 |
| 12 小时制 | 1 | AM/PM（1 = 下午） | 时十位(0/1) | 下午 2 点 → 1 1 0010 = 0x92 |

**改模式后必须重新写一遍小时寄存器**，否则显示会乱。初学者建议固定用 24 小时制：写小时时保证 bit7 = 0，即 `DEC_to_BCD(hour)`（hour ≤ 23 时 BCD 转换结果 bit7 自动为 0）。

### 5.4 写保护寄存器 WP（手册第 7 页）——最重要的一个寄存器

- 控制寄存器（写 0x8E / 读 0x8F）的 bit7 是**写保护位 WP**。
- WP = 1 时，**除 0x8E 本身以外的所有寄存器都拒绝写入**（读不受影响）。
- 手册原文：**"The initial power-on state is not defined. Therefore, the WP bit should be cleared before attempting to write to the device."**（上电状态不确定，写数据前必须先清零。）
- 低 7 位永远读出 0。

两个推论：

1. **任何写操作之前必须先执行 `写 0x8E ← 0x00`**，而且这条写命令本身永远能成功（WP 拦不住对它自己的写入）。所以标准做法是把它放进 `DS1302_Init()`。
2. 调试技巧：**读 0x8F 可以当"通信自检"**。通信正常时返回值只可能是 0x00（已清）或 0x80（未清）；如果返回 0xFF 之类的乱码，说明接线或时序有问题。

另外，DS1302 通常带纽扣电池，寄存器内容（包括 WP 位）掉电后由电池维持——**即使拔掉电源重新上电，WP 也可能还是 1**。这就是为什么每次上电的 Init 里都要清一次。

### 5.5 涓流充电寄存器（0x90，手册第 7 页，可选功能）

bit7~4 = TCS，bit3~2 = DS（二极管选择），bit1~0 = RS（电阻选择）：

| 位段 | 值 | 含义 |
|---|---|---|
| TCS（bit7~4） | 1010 | 唯一能启用充电的值，其它一律禁止 |
| DS（bit3~2） | 01 / 10 | 串 1 只 / 2 只二极管（00、11 禁止） |
| RS（bit1~0） | 01 / 10 / 11 | 2kΩ / 4kΩ / 8kΩ |

充电电流约 `I = (VCC2 − VCC1 − 0.7V) / R`，例如 5V 主电、1 只二极管、2kΩ 时约 2.2mA。**上电默认是禁止状态（0x5C）**。警告：该功能只能给可充电电池或超级电容充电，接普通一次性锂电池会危险；没有此类需求就永远别写这个寄存器。

### 5.6 静态 RAM（0xC0~0xFD）

31 字节，命令字：写 = `0xC0 | (n<<1)`，读 = `0xC1 | (n<<1)`，n = 0~30。用法和时钟寄存器完全一样（同样受 WP 保护），可以用来存闹钟设置、校准值等掉电不丢的数据。

### 5.7 突发模式（Burst Mode，手册第 6、8 页）

命令字 bit5~1 全为 1 即进入突发模式：

- **时钟突发**：写 0xBE / 读 0xBF，一次连续传输 8 个寄存器（秒→分→时→日→月→星期→年→WP）。
  - **时钟突发写必须写满 8 个字节**才会生效（包括最后那个 WP 字节）；WP=1 时突发写整个失败。
  - 突发读时芯片会把当前时间先拷贝到一组影子寄存器再输出，即使读的过程中时间发生进位，读到的 7 个字节也是同一时刻的快照——**不会出现"时读到 23、分却读到下一分钟的 00"这种撕裂**。
- **RAM 突发**：写 0xFE / 读 0xFF，可任意长度，不必写满 31 字节。

## 6. 时序详解（重点）

### 6.1 全景图

一次单字节传输 = **8 位命令字节 + 8 位数据字节 = 16 位**，全部 LSB 先行。CE 在整个 16 位期间保持高，结束时拉低：

```
      ├─────────────── CE = 1，传输进行中 ───────────────┤
CE:  ─┘                                                 └───
SCLK:  ↑1 ↑2 ↑3 … ↑8 ↑9 ↑10 … ↑16        （共 16 个上升沿）
      └─ 命令字节 ─┘└── 数据字节 ──┘
```

写和读的区别只在于数据字节的 8 拍由谁驱动 I/O。

### 6.2 写时序（主机 → DS1302）

手册第 6 页："写命令字节输入完毕后，数据字节在接下来 8 个 SCLK 的**上升沿**输入，从 bit0 开始。"

```
CE :  ____┌──────────────────────────────────────────────────────┐____
          │                     CE = 1                          │
SCLK:  ___│┌┐  ┌┐  ┌┐     ┌┐    ┌┐  ┌┐     ┌┐ _________________
           ││  ││  ││ …   ││    ││  ││ …   ││
           ↑1  ↑2  ↑3     ↑8    ↑9  ↑10    ↑16
I/O :   <C0> <C1> <C2> … <C7>  <D0> <D1> …  <D7>   ← LSB 先行
          └─ 命令字节 ─┘        └─ 数据字节 ─┘
```

每一拍的动作（以命令位 i 为例）：

1. `I/O = 命令位i` —— 数据在上升沿**之前**建立（手册要求建立时间 t_DC ≥ 50ns）；
2. `SCLK = 1` —— **上升沿，芯片锁入这一位**；
3. 数据在 SCLK 高电平期间保持不变（手册要求保持时间 t_CDH ≥ 70ns）；
4. `SCLK = 0` —— 回到低电平，为下一位腾出"安全的电平变化窗口"。

数据字节同理再重复 8 拍。最后 CE 拉低（此时 SCLK 已为低，满足"CE 变化时 SCLK 为低"的要求）。

### 6.3 读时序（DS1302 → 主机）

手册第 6 页"DATA OUTPUT"原文：

> Following the eight SCLK cycles that input a read command byte, a data byte is output on the falling edge of the next eight SCLK cycles. Note that **the first data bit to be transmitted occurs on the first falling edge after the last bit of the command byte is written**.

翻译：读命令写完之后，数据在接下来 8 个下降沿输出；**第一个数据位出现在"命令字节最后一位写完"之后的第一个下降沿上**。

```
CE :  ____┌──────────────────────────────────────────────────────┐____
SCLK:  ___│┌┐  ┌┐  ┌┐     ┌┐──────┐   ┌┐     ┌┐ _________________
           ││  ││  ││ …   ││      │   ││ …   ││
           ↑1  ↑2  ↑3     ↑8    ↓9↓   ↓     ↓16↓
I/O :   <C0> <C1> …  <C7>      <D0>     <D1>…   <D7>
          └─ 主机发命令 ─┘      └────── 芯片输出，主机采样 ──────┘
                          ↑
          命令最后一位的上升沿(↑8)之后的第一个下降沿(↓)
          芯片输出 D0 —— 之后每来一个下降沿，输出下一位
```

每一拍的动作：

1. 命令阶段：和写时序一样，8 个上升沿把命令送进去。**注意命令阶段结束时 SCLK 停在高电平**（原因见 6.4）；
2. 主机把 I/O 的锁存器写 1，释放总线（见 7.4）；
3. 读阶段每拍：`SCLK = 0` 制造一个下降沿 → 芯片在下降沿后最多 200ns（t_CDD，5V）内把新的一位送上总线 → 主机立刻采样；
4. 这一位置到下一个下降沿之前一直有效，所以采样点在下降沿之后越早越好，而且**两次采样之间不要再动 I/O**。

### 6.4 下降沿计数——最经典的"读数错位"bug

读时序的正确性取决于一件事：**命令最后一个上升沿与第一次采样之间，只能恰好出现一个下降沿**。

把命令循环写成"先 1 后 0"（`SCLK=1; SCLK=0;`）就会踩雷：

```c
/* 错误示范 */
for (i = 0; i < 8; i++) {
    DS1302_IO = Command & (0x01 << i);
    DS1302_SCLK = 1;          // 上升沿锁入命令位 —— 没问题
    DS1302_SCLK = 0;          // ← 最后一轮的这句产生了一个多余的下降沿！
}                             //   芯片在这里就提前吐出了 D0
for (i = 0; i < 8; i++) {
    DS1302_SCLK = 1; DS1302_SCLK = 0;   // 这 8 个下降沿输出的是 D1…D7+下一位
    if (DS1302_IO) Data |= (0x01 << i); // 读回的值整体左移了一位
}
```

后果：读回的值 = 正确值整体错一位（例如 59 秒 0x59 读成 0xB2 之类的乱数）。本工程 `DS1302_ReadByte` 的命令循环写成 `SCLK=0; SCLK=1;`，循环结束时 SCLK 停在高电平，读循环里的每个 `SCLK=0` 才正好对应一个数据位——这正是它正确的根本原因。

> 记忆法：**写数据看上升沿，读数据数下降沿；命令阶段停在"高"，读循环从"高"往低落。**

### 6.5 时序参数表（5V 供电，手册第 11 页）

| 参数 | 符号 | 最小值 | 最大值 | 含义 |
|---|---|---|---|---|
| 时钟频率 | f_CLK | DC | **2.0 MHz** | SCLK 上限 |
| 时钟低电平时间 | t_CL | 250 ns | — | |
| 时钟高电平时间 | t_CH | 250 ns | — | |
| 数据建立时间 | t_DC | 50 ns | — | 上升沿前数据须稳定 |
| 数据保持时间 | t_CDH | 70 ns | — | 上升沿后数据须保持 |
| 输出延迟 | t_CDD | — | 200 ns | 下降沿后输出有效 |
| CE 建立时间 | t_CC | **1 µs** | — | CE 拉高到第一个上升沿 |
| CE 保持时间 | t_CCH | 60 ns | — | 最后一个下降沿到 CE 拉低 |
| CE 无效时间 | t_CWH | 1 µs | — | 两次传输之间 CE 为低的时间 |

**为什么 51 上不用加任何延时**：STC89C52 是 12T 经典内核，执行一条 `sbit` 赋值约 1~2 个机器周期（12MHz 时约 1~2µs），加上 C51 循环开销，实际 SCLK 频率只有一两百 kHz，离 2MHz 上限差十几倍；建立/保持/输出延迟都有几十倍裕量。所以 bit-bang 代码里看不到任何 `_nop_()` 是正常的。

**换更快的芯片要注意**：如果移植到 STC8/STC32 等 1T 内核跑高主频，一次 sbit 操作只有几十 ns，`t_CC`（CE 建立 ≥1µs）和 250ns 的脉宽就可能不满足——在 CE 拉高后加几个 `_nop_()` 或短延时即可。

## 7. 驱动代码逐行讲解

### 7.0 先回顾原代码的三个问题

对照 `project/src/DS1302.C`：

1. **`DS1302_Init()` 没有清写保护**——写入可能被芯片静默忽略（见 5.4 节，这是最严重的一个）；
2. **`DS1302_WriteByter(unsigned char Command, Data)` 的 `Data` 没写类型**——按 C90 规则变成隐式 `int`（16 位形参），Keil 不报错但埋雷；函数名 `WriteByter` 也是笔误；
3. **`DS1302_ReadByte` 读数据前没有释放 I/O 口**——现在能工作纯属巧合（读命令最高位恒为 1，引脚恰好留在"写 1"的弱上拉状态），规范写法应显式释放。

下面的参考驱动修正了这三点。**原代码里对的部分也值得夸**：写/读的边沿方向、命令阶段停在高电平、CE 进出时 SCLK 为低，全都符合数据手册。

### 7.1 引脚定义与初始化

```c
#include <STC89C5xRC.H>

sbit DS1302_SCLK = P3 ^ 6;
sbit DS1302_IO   = P3 ^ 4;
sbit DS1302_CE   = P3 ^ 5;

void DS1302_Init(void)
{
    DS1302_CE   = 0;   // CE 拉低：结束任何可能的传输
    DS1302_SCLK = 0;   // SCLK 归零：满足"CE 拉高时 SCLK 必须为低"
    DS1302_WriteByte(0x8E, 0x00);   // ★ 清写保护 WP=0，此后才能写任何寄存器
}
```

`DS1302.h` 中对应的声明（类型必须写全，且与 .C 文件一致）：

```c
void DS1302_Init(void);
void DS1302_WriteByte(unsigned char Command, unsigned char Data);
unsigned char DS1302_ReadByte(unsigned char Command);
```

### 7.2 写一个字节

```c
void DS1302_WriteByte(unsigned char Command, unsigned char Data)
{
    unsigned char i;
    DS1302_CE = 1;                      // 上升沿启动传输（此刻 SCLK 为低，合法）

    for (i = 0; i < 8; i++)             // ── 命令字节，LSB 先行 ──
    {
        DS1302_IO = Command & (0x01 << i);  // ① 先把这一位放到 I/O（建立时间）
        DS1302_SCLK = 1;                    // ② 上升沿：芯片锁入
        DS1302_SCLK = 0;                    // ③ 回到低，下一位可以安全变化
    }
    for (i = 0; i < 8; i++)             // ── 数据字节，同样 8 个上升沿 ──
    {
        DS1302_IO = Data & (0x01 << i);
        DS1302_SCLK = 1;
        DS1302_SCLK = 0;
    }
    DS1302_CE = 0;                      // 结束传输（此时 SCLK 已为低）
}
```

要点：

- 顺序必须是"**先放数据，再拉高时钟**"——数据要在上升沿时有效；
- 循环结束 SCLK 停在低电平，正好满足下一次传输/CE 变化的前提；
- 多余的 SCLK 会被芯片忽略，所以写 16 拍就收工即可；
- Keil 里 `DS1302_IO = 表达式;` 按"**非零即为 1**"处理，所以 `Command & (0x01 << i)` 这种写法是安全的。

### 7.3 读一个字节

```c
unsigned char DS1302_ReadByte(unsigned char Command)
{
    unsigned char i, Data = 0x00;

    DS1302_CE = 1;

    for (i = 0; i < 8; i++)             // ── 命令字节：0→1，结束时 SCLK 停在高 ──
    {
        DS1302_IO = Command & (0x01 << i);
        DS1302_SCLK = 0;                // 拉低（为上升沿做准备）
        DS1302_SCLK = 1;                // 上升沿：锁入命令位
    }                                   // ★ 循环结束时 SCLK = 1

    DS1302_IO = 1;                      // ★ 释放总线：向锁存器写 1，引脚进入可读状态

    for (i = 0; i < 8; i++)             // ── 数据字节：每个下降沿出一位 ──
    {
        DS1302_SCLK = 1;                // 保持高（第一轮是空操作）
        DS1302_SCLK = 0;                // ★ 下降沿：芯片输出下一位
        if (DS1302_IO)                  // 下降沿后立即采样
            Data |= (0x01 << i);
    }

    DS1302_CE  = 0;                     // 结束传输
    DS1302_IO  = 0;                     // 总线交还，留个确定电平
    return Data;                        // 返回的是 BCD 码！
}
```

三个"★"就是读函数的全部精髓：

1. **命令循环 0→1**：保证命令字节用 8 个上升沿送完，且结束时 SCLK 停在高电平——这样读循环的第一个下降沿恰好是"命令最后一位之后的第一个下降沿"，芯片在这时输出 D0（见 6.3/6.4 节）。
2. **先释放总线再读**：见下一节。
3. **读循环 1→0**：每拍制造一个下降沿，随后立刻采样。

### 7.4 为什么读之前要向 I/O 写 1？（51 准双向口原理）

P3 是"准双向口"：每个引脚内部有个锁存器，**锁存器写 0 时内部 MOS 管把引脚钳死在 GND**，外部器件说什么都读不到（永远读到 0），芯片想输出高电平还得跟这只 MOS 管打架（总线冲突）；锁存器写 1 时引脚靠内部弱上拉保持高，外部器件可以随意驱动它——这才叫"能读"。

所以读外部器件前必须 `DS1302_IO = 1;`。原来的代码没写这句也能跑，是因为读命令（如 0x81）的最高位 R/W=1 恰好是最后移出的命令位，引脚碰巧留在了"写 1"状态。一旦换成别的命令字或者改了循环顺序，就会读出全 0。

### 7.5 小结：驱动层必须满足的硬性清单

| # | 要求 | 出处 |
|---|---|---|
| 1 | Init 里清 WP（0x8E ← 0x00） | 手册第 7 页 |
| 2 | 一切字节 LSB 先行 | 手册第 5 页 |
| 3 | 写：先放数据再给上升沿，高电平期间保持 | 手册第 6 页 |
| 4 | 读：命令阶段停在 SCLK=1，读循环每个下降沿出一位 | 手册第 6 页 |
| 5 | 读前释放 I/O（向锁存器写 1） | 51 准双向口特性 |
| 6 | CE 拉高时 SCLK 必须为低；CE 拉低时最后也停在低 | 手册第 6 页 |
| 7 | 读回的是 BCD，显示前要转换 | 手册第 6 页 |

## 8. 应用层：设置与读取时间

### 8.1 BCD 转换（必须会背的两行）

DS1302 的时间寄存器是 BCD 码：高 4 位是十位，低 4 位是个位。

```c
unsigned char BCD_to_DEC(unsigned char bcd)  /* 0x59 -> 59 */
{
    return (bcd >> 4) * 10 + (bcd & 0x0F);
}

unsigned char DEC_to_BCD(unsigned char dec)  /* 59 -> 0x59 */
{
    return ((dec / 10) << 4) | (dec % 10);
}
```

不转换的典型症状：写 0x59 读回显示 089（0x59 按十进制解释是 89）；59 秒显示成 89 秒。

### 8.2 设置时间：把"秒"留到最后写

手册第 6 页有个容易被忽略的细节：**每次写秒寄存器都会把内部分频链复位**，所以设时间时要把其余寄存器在写秒之后的 1 秒内全部写完——最省心的做法就是**秒最后写**（51 连写 7 个寄存器不到 1ms，裕量巨大）。

```c
/* 24 小时制。参数全部用十进制，星期 1~7 编码自定义 */
void DS1302_SetTime(unsigned char year, month, date, week, hour, min, sec)
{
    DS1302_WriteByte(0x8C, DEC_to_BCD(year));  /* 年 00~99 */
    DS1302_WriteByte(0x8A, week);              /* 星期，不用 BCD，1~7 直接写 */
    DS1302_WriteByte(0x88, DEC_to_BCD(month));
    DS1302_WriteByte(0x86, DEC_to_BCD(date));
    DS1302_WriteByte(0x84, DEC_to_BCD(hour));  /* 24h 制：bit7=0 自动满足 */
    DS1302_WriteByte(0x82, DEC_to_BCD(min));
    DS1302_WriteByte(0x80, DEC_to_BCD(sec));   /* ★ 秒最后写；bit7(CH)=0 顺带启动时钟 */
}

void DS1302_ReadTime(unsigned char *year, unsigned char *month, unsigned char *date,
                     unsigned char *hour, unsigned char *min, unsigned char *sec)
{
    *year  = BCD_to_DEC(DS1302_ReadByte(0x8D));
    *month = BCD_to_DEC(DS1302_ReadByte(0x89));
    *date  = BCD_to_DEC(DS1302_ReadByte(0x87));
    *hour  = BCD_to_DEC(DS1302_ReadByte(0x85));
    *min   = BCD_to_DEC(DS1302_ReadByte(0x83));
    *sec   = BCD_to_DEC(DS1302_ReadByte(0x81));
}
```

注意 24 小时制下 `DEC_to_BCD(hour)`（hour ≤ 23）的结果 bit7 恒为 0，正好是 24h 模式；如果想用 12 小时制，要按 5.3 节的格式手动拼 AM/PM 位。

### 8.3 在 LCD1602 上显示走时的时钟

```c
#include "DS1302.h"
#include "LCD1602.h"
#include "Com_Util.h"

void main(void)
{
    unsigned char h, m, s;

    LCD_Init();
    LCD_ShowString(1, 1, "RTC Clock");

    DS1302_Init();                                   /* 每次上电必须：清写保护 */
    DS1302_SetTime(26, 10, 25, 1, 23, 59, 50);       /* 首次使用设一次时间；
                                                        不需要每次校时的话删掉这行 */

    while (1)
    {
        h = BCD_to_DEC(DS1302_ReadByte(0x85));
        m = BCD_to_DEC(DS1302_ReadByte(0x83));
        s = BCD_to_DEC(DS1302_ReadByte(0x81));

        LCD_ShowNum(2, 1, h, 2);
        LCD_ShowChar(2, 3, ':');
        LCD_ShowNum(2, 4, m, 2);
        LCD_ShowChar(2, 6, ':');
        LCD_ShowNum(2, 7, s, 2);

        Delayms(200);
    }
}
```

说明：

- 分三次单独读寄存器在秒进位瞬间可能读到"撕裂"的组合（23:59:59 过渡瞬间读到 23:00:00），演示无碍；要严格一致就改用 10.1 节的突发读。
- `DS1302_SetTime` 只在**首次使用（新芯片/换过电池）**时需要，之后这行可以删掉——时间由纽扣电池维持，断电也不丢。

### 8.4 一块新芯片的标准上电流程

```
第一次使用（出厂态）：
    DS1302_Init()          → 清 WP
    DS1302_SetTime(...)    → 写入正确时间（写秒时顺带把 CH 清 0，时钟开始走）
    之后正常 ReadTime

以后每次上电：
    DS1302_Init()          → 只需清 WP（因为 WP 上电状态不确定）
    直接 ReadTime          → 时间由纽扣电池维持着，接着上次的走
```

## 9. 故障排查表

| 现象 | 最可能原因 | 排查方法 |
|---|---|---|
| 写入无效，读回旧值/0 | **WP 没清**（Init 里少了 0x8E←0x00） | 读 0x8F：返回 0x80 说明仍在写保护 |
| 时间不走，数值不变 | **CH=1**（新芯片上电状态不确定） | 写秒时保证 bit7=0（正常写秒值即可） |
| 显示的数字很大/很怪 | **BCD 没转换**（0x59 显示成 89） | 加 BCD_to_DEC |
| 读回值像"整体错一位" | 命令循环写成了先 1 后 0，**多了个下降沿** | 命令阶段必须停在 SCLK=1（见 6.4） |
| 读回全是 0 | 读前没释放 I/O / 接线松 | `DS1302_IO=1;`；查三根线 |
| 读回 0xFF 或乱码 | SCLK 极性反了 / 晶振没起振 / 供电异常 | 对着 6.4 清单逐拍核对；换晶振试 |
| 读 0x8F 返回非 0x00/0x80 | 通信本身不通 | 先解决接线/时序，再谈功能 |
| 时钟快慢异常 | 晶振负载电容不匹配 / 晶振布线受干扰 | 用 CL=6pF 的表晶，布线远离干扰源 |
| 断电后时间丢失 | VCC1 电池没电/装反/VCC2 未接主电 | 万用表测电池电压，查电源切换 |
| 移植到 STC8 等高速芯片后通信乱 | t_CC（CE 建立 1µs）等时序不满足 | CE 拉高后加几个 `_nop_()`（见 6.5） |

**通用调试三板斧**：① 读 0x8F 验证通信通不通；② 写 0x80←0x55 再读 0x81 验证 WP 和写入路径；③ 都通了再上完整时钟逻辑。

## 10. 进阶：突发模式、RAM、涓流充电

### 10.1 时钟突发读（一次拿走同一时刻的 7 个时间值）

```c
/* 读出 秒,分,时,日,月,星期,年,WP 共 8 字节（BCD），存入 buf[0..7] */
void DS1302_ReadClockBurst(unsigned char *buf)
{
    unsigned char i, j, Command = 0xBF;

    DS1302_CE = 1;
    for (i = 0; i < 8; i++) {              /* 命令字节：0→1，停在高 */
        DS1302_IO = Command & (0x01 << i);
        DS1302_SCLK = 0;
        DS1302_SCLK = 1;
    }
    DS1302_IO = 1;                          /* 释放总线 */

    for (j = 0; j < 8; j++) {              /* 连续 8 个字节，中间不停顿 */
        buf[j] = 0;
        for (i = 0; i < 8; i++) {
            DS1302_SCLK = 1;
            DS1302_SCLK = 0;               /* 每个下降沿出一位 */
            if (DS1302_IO) buf[j] |= (0x01 << i);
        }
    }
    DS1302_CE = 0;
}
```

要点：字节之间**不要**动 CE、不要重新发命令，芯片内部地址会自动连续递增——这就是 6.1 节说的"多给 SCLK 就重复输出"的用法。突发读拿到的是同一时刻的快照，`main` 里用它替换 8.3 节的三次单读可以彻底消除撕裂。

突发写（0xBE）必须一次写满 8 字节（秒→分→时→日→月→星期→年→WP），且写之前 WP 必须已清零，否则整个传输作废。

### 10.2 RAM 的读写

```c
void DS1302_WriteRAM(unsigned char addr, unsigned char dat)  /* addr: 0~30 */
{
    DS1302_WriteByte(0xC0 | (addr << 1), dat);
}

unsigned char DS1302_ReadRAM(unsigned char addr)
{
    return DS1302_ReadByte(0xC1 | (addr << 1));
}
```

RAM 同样受 WP 保护和电池备份，适合存"闹钟时刻、音量等级"这类掉电不丢的小数据。

### 10.3 写保护的高级用法：设完时间重新上锁

对可靠性有要求的产品可以这样用 WP：

```c
DS1302_WriteByte(0x8E, 0x00);   /* 解锁 */
DS1302_SetTime(...);            /* 对表 */
DS1302_WriteByte(0x8E, 0x80);   /* 上锁：程序跑飞也改不了时间 */
```

平时要改时间再解锁。学习阶段用"只解锁不上锁"就够了。

## 11. 附录：速查卡

### 命令字一览

| 操作 | 命令字 | 操作 | 命令字 |
|---|---|---|---|
| 写/读 秒 | 0x80 / 0x81 | 写/读 年 | 0x8C / 0x8D |
| 写/读 分 | 0x82 / 0x83 | 写/读 WP | 0x8E / 0x8F |
| 写/读 时 | 0x84 / 0x85 | 写/读 涓流充电 | 0x90 / 0x91 |
| 写/读 日 | 0x86 / 0x87 | 时钟突发 写/读 | 0xBE / 0xBF |
| 写/读 月 | 0x88 / 0x89 | RAM 突发 写/读 | 0xFE / 0xFF |
| 写/读 星期 | 0x8A / 0x8B | 写/读 RAM[n] | 0xC0/(0xC1) + 2n |

### 十条军规

1. 写任何寄存器前，先 `0x8E ← 0x00` 清 WP（上电状态不确定，电池还会保持它）。
2. 所有字节 LSB 先行；写命令 = 0x80|(地址<<1)，读命令 = 写命令+1。
3. 写数据：先放 I/O 再给上升沿，SCLK 高电平期间保持不动。
4. 读数据：命令阶段停在 SCLK=1；每来一个下降沿出一位，下降沿后立刻采样。
5. 读之前向 I/O 锁存器写 1 释放总线；读完给总线留个确定电平。
6. CE 拉高时 SCLK 必须为低；传完先把 SCLK 落回低再拉低 CE。
7. 时间寄存器全是 BCD，显示前转换；写进去之前用 DEC_to_BCD。
8. 秒寄存器 bit7 是 CH：写秒时顺带清 0，时钟才会走。
9. 小时寄存器 bit7 是 12/24 选择：改模式必须重写小时；初学固定用 24h 制。
10. 设时间时秒最后写（写秒会复位分频链，其余寄存器要在这之后 1 秒内写完）。
